# AGENTS.md

## Project state

- Astro 7 + TypeScript + Tailwind CSS site. The source specification is `ServerPilot_Website_MVP_Astro_Specification.pdf`; the spec uses "ServerPilot" as a working name.
- The shipped product name is **ServerDesk**, with brand assets in `public/` and production domain `https://serdesk.srosthai.me`. Use ServerDesk in all site content and naming.
- Source of truth for visual and product requirements remains the specification. Read it before changing page structure or product claims.

## Commands

```bash
npm install
npm run dev
npm run check
npm run build
npm run preview
```

Run `npm run check` and `npm run build` before committing. The build is static; no SSR adapter.

## What is being built

- Astro + TypeScript + Tailwind CSS marketing site for ServerDesk, a locally installed desktop app for managing VPS servers over SSH.
- Static pages: Home, Features, Download, Documentation, Changelog, About.
- React islands only for genuinely interactive pieces (OS selector, screenshot gallery/lightbox, hero background). Do not build the site in React.
- Content Collections for documentation and changelog. Data files for features and releases (`src/data/features.ts`, `src/data/releases.ts`).
- Follow the structure in spec section 7 unless there is a concrete reason to deviate.
- Deployment target: Cloudflare Pages, static output. `main` is the production branch. Feature branches merge to `dev`, then `dev` to `main`. The `production` branch is not used. Downloads point to GitHub Releases or another stable host.

## Content rules (strict)

- Only describe features present in the current build. Mark incomplete capabilities "Coming soon" or omit them.
- Never invent download counts, ratings, testimonials, customer logos, compatibility claims, or platform badges.
- Show only installers that actually exist for the current release, with real version, date, size, architecture, and checksum when available.
- OS detection may be a convenience, but explicit Windows/macOS/Linux choices must always be visible.
- Real application screenshots only. Never fabricate UI. Screenshots in `public/screenshots/` come from the actual app and may show disconnected or empty states honestly.
- Local-first claims must stay accurate: the app runs locally and connects directly over SSH, but data is exchanged with the remote server, so do not claim no data ever leaves the machine.
- "Free to use" refers to ServerDesk only. Do not imply VPS hosting is free.

## Design constraints

- Strict monochrome palette: `#FFFFFF`, `#F5F5F5`, `#6B6B6B`, `#E5E5E5`, `#111111`. Text gray is `#6B6B6B` for WCAG AA; `#737373` is the decorative spec value. No accent colors in site chrome. The color logo mark is the only brand exception.
- Theme: light and dark modes use semantic CSS variables under `html.dark`. Use tokens such as `bg-paper`, `text-ink`, `text-graphite`, `border-rule`, `bg-band`, and `text-band-foreground`; do not hardcode theme colors. The toggle persists in `localStorage` and falls back to system preference.
- Type: Geist Sans for text; Geist Mono for technical labels. Content max width ~1200px. Minimum UI text size is 14px.
- Animation: use `ScrollRevealHeading` for below-fold section headings and the React Bits `AnimatedContent` wrapper for below-fold card groups. Keep the hero H1 and above-fold content static. Use `ScreenshotFigure.astro` for captioned app screenshots; it provides the native popup dialog.
- Thin borders and whitespace over shadows. Corner radius 10px for controls, 14px for panels.
- Motion: short CSS transitions (150-500ms), IntersectionObserver for reveals, `prefers-reduced-motion` support. No parallax, constant motion, heavy 3D, or WebGL except the hero Threads background, which must respect reduced motion and only hydrates at 1024px and above.
- Pages must remain readable without client-side JavaScript; keep main content server-rendered. Hide the theme toggle and scroll-to-top control when JS is unavailable.
- Avoid fixed-width screenshot containers that cause horizontal overflow on mobile.

## SEO and brand assets

- Production URL: `https://serdesk.srosthai.me`. `SITE_URL` can override it at build time.
- Shared image: `public/og-image.png` (1200x630). Logo mark: `public/logo-mark.png` for favicon and manifest, `public/logo-mark-64.png` for the header. Apple touch icon: `public/apple-touch-icon.png`.
- Release data lives in `src/data/releases.ts`. v0.1.0 is a published GitHub pre-release; direct asset links and SHA-256 checksums must stay in sync with the GitHub release.
- Every page needs a unique title, description, and canonical URL. Sitemap is generated by `@astrojs/sitemap`; `public/robots.txt` points at it.
- Structured data must contain only verified facts. Do not add ratings, reviews, or invented offer claims.

## Out of scope

- User accounts, cloud dashboard, hosted monitoring backend, public forum/support portal, CMS, heavy 3D/WebGL, unverified marketing claims.
